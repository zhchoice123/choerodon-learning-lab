# 运行与部署边界

## 支持的运行方式

本地运行使用单人开发模式：`yarn start` 同时启动 CRA 编译服务、本地学习 API、Monaco 资源路由和 mock。保存练习会写入源码文件，开发服务器重新编译后更新页面。

安装后复制 `.env.example` 为 `.env.local`，默认 `HOST=127.0.0.1`、`PORT=3000`。若端口被占用，先查看原终端确认服务身份；需要另一个实例时在该实例配置不同端口。mock 和中间件变更不随前端热更新生效，必须重启对应进程。

数据存储：

| 内容 | 位置 | 重启后 |
| --- | --- | --- |
| 当前练习 | src/units/*/Exercise.js | 保留 |
| 重置前备份 | .backup/ | 保留，默认不进 Git |
| mock 增删改 | 各模块独立内存 | 恢复种子数据 |
| 浏览器中未保存的编辑 | 编辑器内存 | 不保证保留 |

## build 的用途

`yarn build` 用于检查生产编译并输出前端资源。`src/setupProxy.js` 不会打包成后端服务，因此单独托管 build/：

- 无法读取、保存、重置练习源码或获取单元 README。
- 无法提供 `/__learn/monaco` 资源，编辑器可能停留在加载状态。
- 没有 `/mock/`，需要业务查询的预览无法正常取数。
- 没有练习保存后的热编译机制。

接口不可用的提示是错误降级，不是完整的静态站点模式。当前路径按站点根目录设计；挂在已有网站的 `/learn/` 等子路径也需要适配资源、API 与开发服务器连接路径。

## 远程个人学习

不需要为了本项目升级服务器的全局 Node。若要远程运行，可为项目安装独立的 Node / Yarn，在单独目录和端口以普通用户启动，并保持仅监听服务器回环地址。更换 Node 主版本必须重新验证，固定旧版本环境不应作为长期公网服务的安全基线。

例如服务在服务器的 127.0.0.1:3000 上运行时，从自己电脑建立隧道：

```bash
ssh -N -L 127.0.0.1:3002:127.0.0.1:3000 your-server-alias
```

再访问自己电脑的 `http://127.0.0.1:3002/#/`。将示例 SSH 别名换成自己的配置。该 SSH 隧道示例本次未单独执行。腾讯云现已切换为独立浏览器身份模式，见 [部署与运维](../deployment/README.md) 和 [浏览器身份验收](browser-identity-verification.md)。

## 公网与多人模式

本地 `yarn start` 不提供身份隔离，不能直接公开。云端入口改用 `deployment/cloud-server.js`：以签名 Cookie 自动识别浏览器、独立存储练习和备份、按访客创建 mock，并通过不透明来源 iframe 预览。编译采用固定插件，只做语法转换，不执行访客代码。

使用 `node deployment/build-cloud.js` 生成独立的 `cloud-build/`，再按 [部署与运维](../deployment/README.md) 配置 HTTPS、持久目录、签名密钥、资源限制。用户无需账号密码，也不按 IP 合并身份；清除 Cookie 后无法自动找回旧作业。该模式没有跨设备账户体系，也不支持任意 npm 包或任意项目代码。
