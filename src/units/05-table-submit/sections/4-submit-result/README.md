# 05-4 提交结果：submit 的三种返回值

## 这一节学什么

`submit()` 不只有「成功 / 失败」：它会先校验，可能根本没发请求。要按返回值分别处理。

## 核心概念

```js
const response = await ds.submit();
if (response === false) { /* 校验没通过 */ }
else if (response)      { /* 成功：后端响应 */ }
else                    { /* undefined：没有发出请求 */ }
// 请求失败（4xx / 5xx）会抛异常，用 try / catch 处理
```

| 返回 | 含义 |
|---|---|
| `false` | 校验没通过，没有发请求 |
| 后端响应 | 保存成功 |
| `undefined` | 没有可提交的数据或配置，没有发请求 |
| 抛异常 | 请求发出去了，但后端返回错误 |

保存成功后：新记录拿到后端分配的 `id`，`status` 变成 `sync`，`dirty` 变回 `false`。

## 看样例

1. 点「新增」不填就保存：提示「校验未通过」，Network 里没有请求
2. 填好再保存：提示成功，ID 列出现后端分配的 id，status 变成 sync
